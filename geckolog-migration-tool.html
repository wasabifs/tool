GeckoLog 搬遷小工具

可以用來:① 修正資料庫裡的擁有者 uid(第 4 步)、② 把 Storage 裡的檔案搬到新專案(第 5 步)。第 1~3 步是給「資料庫裡有 base64 圖片要順便轉存壓縮」的情境用的,如果 GeckoLog 資料庫已經用官方匯出/匯入搬完了、也沒有這種 base64 圖片問題,可以跳過第 3 步,直接做第 1、2 步登入後,去用第 4、5 步就好。

用之前確認一下:新專案的 Firestore 規則要先暫時放寬(搬完之後記得換回嚴格版本): 
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
Storage 的規則也要暫時允許已登入使用者寫入。另外這個頁面要放到 https:// 網址下開啟（例如 GitHub Pages）,不能用 file:// 直接雙擊打開,不然 Google 登入會失敗。

4. 修正擁有者 uid(全部搬完後，最後做這步)

搬過去的文件，記錄擁有者的欄位還是舊帳號的 uid，要改成新專案裡實際在用的帳號 uid，資料才能被正常讀到。這一步只動新資料庫，不會碰舊專案。可以跑好幾個集合，用逗號分開。不同集合、甚至同一個集合裡，欄位名稱可能不一樣（例如 uid、buyerUid、createdBy），欄位名稱不同就要分開跑幾次。這裡填的集合名稱一律用「集合群組」方式查詢，所以不管是最上層的集合，還是藏在某份文件底下的子集合（例如 geckos/xxx/equipment），都找得到。
